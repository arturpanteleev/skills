# Карточка задачи спринта

Поля подбираются по типу работы; не заполняй формальные пустышки.

- **ID и заголовок:** стабильный короткий код и конкретный результат.
- **Группа, тип и приоритет:** продукт/код/доступ/исследование; приоритет владельца или явно обозначенное предложение.
- **Сейчас / проблема:** наблюдаемое поведение, источник и границы проверки.
- **Цель:** что изменится для пользователя или какое решение нужно получить.
- **Действия и границы:** что входит, какие ошибки и крайние случаи существенны.
- **Приёмка:** наблюдаемый результат и способ проверки; тесты — когда нужны.
- **Зависимости и блокеры:** права, решения, другие задачи, ответственный — только если известен.
- **Опора:** кейсы, код, Jira, PR и результаты проверок с датой.
- **Состояние:** статус работы, официальный статус Jira, PR/CI и оставшаяся приёмка отдельно.

## ID и связи

У задачи спринта может быть свой код `FB-01`, `S-1` и отдельный список Jira-ключей. Существующий код не заменяется Jira-ключом: якоря, история и сохранённые статусы зависят от него. Одна задача может быть связана с несколькими Jira-карточками и PR. Новым задачам выдавай новые ID; не переиспользуй удалённые и не перенумеровывай остальные.

Не создавай Jira-задачу только ради заполнения колонки. До создания покажи подготовленную структуру в артефакте; создание выполняй, когда это входит в запрос и правила проекта.

## Приоритет и свидетельства

P0 — немедленный подтверждённый блокер; P1 — серьёзное влияние/срочность; P2 — плановое улучшение; P3 — низкая срочность. Не выдавай свою оценку за приоритет владельца. Для непроверенной гипотезы не назначай P0/P1 самостоятельно; пожелание владельца может иметь высокий бизнес-приоритет без доказанного дефекта.

Количество задач определяется содержанием и выбранным объёмом, а не лимитом 15. Большой список группируй; активную очередь выделяй отдельно, сохраняя остальной бэклог.
