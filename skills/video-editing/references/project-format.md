# project.json, схема 1

Все пути внутри JSON относительны папке самого project.json; абсолютные тоже допустимы, но ухудшают переносимость. Имя `source1` — произвольный идентификатор файла в sources. Время — секунды от начала исходника после автоповорота, не таймкод ролика.

Пример: `../assets/project.example.json`. Замени файлы и интервалы после визуального анализа. `init` создаёт пустой clips намеренно: скрипт не выдумывает, какие кадры красивы.

| Поле | Значение |
|---|---|
| schema_version | 1 |
| title, date | Название, дата пользовательского проекта |
| sources | Словарь id → путь к оригинальному файлу |
| clips | Упорядоченные объекты source, in, out, action, reason; необязательный crop |
| music | null для немого ролика либо объект path, start, bpm, credit, fade_out, lufs |
| output | width, height (чётные пиксели), fps (целое 1–120), preset |
| crop | Необязательное глобальное окно x, y, width, height |

Crop задаётся в пикселях **отображаемого** кадра после поворота. Значения чётные для точного расположения 4:2:0. Соотношение сторон окна должно совпадать с выходом: растяжения или чёрных полей скрипт автоматически не добавляет. Crop у клипа заменяет глобальный. `crop: null` у клипа отключает глобальный crop для него.

Пример: вертикальный источник 1080×1920 → crop `{ "x":0, "y":0, "width":1008, "height":1792 }` → 1080×1920. Масштаб 107,14%, убрано справа/снизу по 6,67% стороны. Это решение для конкретной композиции с сумкой, не дефолт для других видео.

Длина части округляется до ближайшего целого кадра при output.fps. Это может повторить/пропустить кадры VFR при приведении к постоянной сетке; пиксельная идентичность обычного экспорта не обещается. Число кадров каждой части проверяется до объединения. Общая длина рассчитывается по числу кадров, не по повторному сложению десятичных секунд.

Музыка стартует с music.start; её должно хватить до конца ролика. start по умолчанию 0, fade_out 0,24 с, lufs -16. Исходный звук клипов в этом renderer выключен. Если нужна речь/звук зала, расширь микширование явно. BPM и credit — данные для анализа/сценария; они не гарантируют музыкальную синхронизацию и не вписывают кредит в картинку.

Команды не перезаписывают готовый MP4 или существующий parts/<version>. Выбирай новую версию. Файл .partial.mp4 и лог сохраняются после ошибки; изучи их до ручного удаления. JSON со снимком рендера лежит в versions/<version>; пути в нём нужно интерпретировать относительно исходной папки проекта, он архив решений, не автономный вложенный проект.
