# Проверка пакета

Создан и проверен 19.11.26 на macOS, Python 3.14.7, FFmpeg 9.0.2, libx264/libx265. Для анализа использованы Pillow, NumPy и SciPy в venv. Это описание локального теста, не сертификат совместимости со всеми ОС и агентами.

Выполнено через фактический CLI:

- doctor: наличие FFmpeg/ffprobe и обоих кодеков.
- init, inspect, validate, scenario, render, verify на небольшом SDR fixture, 2 части по 1,2 с: 72 кадра, 2,4 с, исходные 320×180 и цветовые теги сохранены.
- reframe готового MP4 с сохранением соотношения сторон и проверкой результата.
- Реальный оригинал йоги с поворотом 90° и 10-битным HLG: 3 выбранные части по 0,8 с, crop от левого верхнего угла, экспорт 360×640, музыка, 72 кадра, совпадающие HLG/BT.2020/10-bit характеристики.
- Контактный лист по точным seek-временам, анализ музыки с ориентиром 100 BPM.
- Ожидаемые отказы: повторная версия, интервал за концом исходника, несовпадающее соотношение сторон crop.
- Структура скилла: quick_validate из skill-creator; Python-модули компилируются.

Для воспроизведения минимальной SDR-проверки, без личных видео:

```bash
python3 /path/to/video-editing/scripts/smoke_test.py
```

Она создаёт временную папку, синтетический тестовый шаблон FFmpeg и отчёт smoke_results.json. Это технический fixture, не AI-генерация и не материал итогового ролика. Папка сохраняется для изучения; путь выводится в конце.

Дополнительная проверка именно оригинала йоги использует `--hdr-source` и `--music`. Эти параметры предназначены для данного известного исходника: интервалы и crop в тесте не универсальны. Команды основного video.py принимают произвольные подходящие источники/проекты. Никаких личных видео и треков внутри пакета нет.

В Claude Code, OpenCode, Pi и BB исполнение ещё не проверено. Использованы обычный формат SKILL.md и Python subprocess без зависимостей от конкретного harness. У каждого агента должны быть собственные права на чтение файлов и запуск локальных инструментов.
