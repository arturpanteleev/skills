# Монтаж оригинальных видео

Скилл работает через локальные Python + FFmpeg/ffprobe, без зависимости от API конкретного harness. Определяй путь `<skill>` по местоположению этого SKILL.md, а не по cwd. Скрипты исполняются из `scripts/`; документация находится в `references/`.

## Подготовка

Прочитай [workflow.md](references/workflow.md) перед монтажом. Запусти `python3 <skill>/scripts/video.py doctor`. Python 3.10+ и FFmpeg обязательны; Pillow нужен для контактных листов, NumPy/SciPy — для музыкального анализа. Установка и подключение к Codex, Claude Code, OpenCode: [portability.md](references/portability.md).

Проверь исходники через `inspect`, затем просматривай контактные листы и точные кадры вокруг движений. JPEG показывает композицию, но не служит эталоном HDR-цвета. Не утверждай, что прослушал звук, если фактически оценивал только численные признаки.

## Процесс

1. Папка видео — `ДД.ММ.ГГ название` в корне рабочего проекта. Внутри: `source/`, `parts/`, `music/`, `analysis/`, `output/`, `versions/`, `project.json`, `сценарий.md`, `проверка.md`. Оригиналы не изменяй. Дату бери из пользовательского контекста, не из часового пояса сервера.
2. Визуально выбери выразительные движения, взгляды, резкие и хорошо скомпонованные кадры. Не склеивай два похожих оборванных движения так, будто это одно. Сам по себе бит не оправдывает неудачный стык.
3. Если нужна музыка, возьми предоставленный файл либо найди разрешённый трек доступными средствами поиска. Сохрани автора, страницу, лицензию и атрибуцию в `music_credit.txt`. Анализ ритма и энергии даёт кандидаты для проверки; не выдавай максимум RMS за достоверную кульминацию.
4. Запиши решения в `project.json` по [project-format.md](references/project-format.md). Пример — [project.example.json](assets/project.example.json). Команда `scenario` создаёт сценарий с таймкодами и обоснованиями до сборки. Отдельного подтверждения сценария не требуй, если сборка уже поручена; соблюдай явное требование пользователя дождаться ответа.
5. Собери `render project.json --version v1`. Нарезки сохраняются в `parts/v1/`, итоговый MP4 — в `output/`, снимок проекта/сценария — в `versions/v1/`. При исправлении меняй данные проекта, а не создавай новый одноразовый Python-скрипт на каждую правку.
6. Выполни `verify OUTPUT.mp4 --plan project.json --report analysis/report.json`. Затем визуально проверь стыки, непрерывность движений и кадрирование, прослушай при наличии такой возможности. Обнови `проверка.md` по фактическим результатам. Автоматические проверки не заменяют художественную оценку.
7. Отдай MP4 и сценарий, кратко опиши изменения и существенные ограничения. Если музыка требует атрибуции, укажи файл с текстом для публикации. Публикация или отправка другим людям требует отдельного поручения.

## Настройки и правки

- Длительность, вступление и минимальная длина кадра определяются задачей. Йога 16,6 с / вступление 4 с / остальные фрагменты 1,8 с — пример, не обязательный шаблон.
- Прямые склейки, скорость 1×, естественные цвета — исходная точка. Заголовки и эффекты добавляй по смыслу запроса. Не менять внешность и не генерировать AI-кадры.
- Финал собирай из оригиналов с одним этапом сжатия каждой выбранной части; объединение частей копирует видеопоток. `parts/` доступны пользователю и сохраняются. Не накапливай пережатия экспортов.
- Правка только готового MP4 (приближение/смещение) допустима через `reframe`, без изменения склеек и звука. Для позднего чистового рендера перенеси crop в project.json и собирай из оригиналов.
- Экспорт по умолчанию — `quality`: обычное качественное сжатие с потерями и разумным размером. «Качество не должно теряться» не означает автоматически математический lossless. Lossless — по явному требованию точных пикселей; объясни размер заранее. Не обещай идентичность после масштабирования.
- Сохраняй битность и HDR/SDR. Не применять LUT или самодельный HDR→SDR tone mapping автоматически. Профили, ограничения и оценка размера: [quality.md](references/quality.md).

## Команды

Вызов: `python3 <skill>/scripts/video.py COMMAND`. Если Python называется `python`, используй его. Подробные аргументы — `COMMAND --help`.

```text
doctor
init ROOT --date 19.11.26 --name "йога классис" --source INPUT.mp4
inspect INPUT.mp4 --report analysis/source.json
contacts INPUT.mp4 --output analysis/contact.jpg --start 0 --end 30 --step 2
analyze-music TRACK.mp3 --output analysis/music.json --bpm 100
validate project.json
scenario project.json
render project.json --version v1 --preset quality
verify OUTPUT.mp4 --plan project.json --report analysis/verification.json
reframe INPUT.mp4 --crop 0 0 1008 1792 --output OUTPUT_crop.mp4
```

Renderer поддерживает прямые склейки на 1×, одну музыкальную дорожку либо немой ролик, постоянное кадрирование, SDR 4:2:0 и HLG 10-bit 4:2:0. Титры, микс исходного звука/речи, произвольные переходы, speed ramps и PQ/Dolby Vision встроенным скриптом не реализованы. Неподдерживаемую функцию расширяй явно и проверяй; не игнорируй параметры молча. Не называй переносимость на другой harness проверенной, пока там фактически не запускал.
