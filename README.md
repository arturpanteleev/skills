# Мои скиллы для ИИ

Общий каталог личных навыков для Codex, Claude Code и OpenCode на одном компьютере.
Оригиналы хранятся в `skills/`, окружения используют симлинки на эти папки.
Правки через любой из трёх путей меняют один и тот же файл в этом репозитории.

```text
skills/
├── skills/flash-sprint/      # SKILL.md, references, agents, scripts и assets при необходимости
├── tools/skills.py          # импорт, установка, инвентаризация и проверки
└── tests/                   # изолированные проверки файловых операций
```

## Начало работы

Нужны Python 3.10+ и [uv](https://docs.astral.sh/uv/). Инструмент сам подготавливает
изолированную зависимость PyYAML; системный Python не меняется. Первый запуск требует
загрузки зависимости, последующие используют кэш uv.

Из корня репозитория:

```sh
./tools/skills.py check
./tools/skills.py install
./tools/skills.py status
```

`install` подключает каждый скилл из каталога:

- Codex: `~/.codex/skills/<имя>`;
- Claude Code: `~/.claude/skills/<имя>`;
- OpenCode: `~/.config/opencode/skills/<имя>`.

Путь к репозиторию определяется по инструменту, поэтому его можно вызвать из любой
папки по абсолютному пути. Если репозиторий перемещён, повторный `install` покажет старые
ссылки как конфликты; после проверки можно заменить их с резервным копированием.

OpenCode также может находить определения в каталогах Claude и `.agents`. Установки
с одинаковым именем здесь указывают на один оригинал. Собственные определения этого
имени в проекте или другом каталоге могут перекрыть глобальное — проверяйте источник.
Новые навыки могут потребовать нового чата/перезапуска окружения; инструмент проверяет
файлы и ссылки, а не внутренний кэш приложения.

## Добавить скилл

Создать `skills/<имя>/SKILL.md` с YAML-полями `name` и `description`, положить рядом
нужные references/scripts/assets. Техническое имя — lowercase kebab-case, например
`flash-sprint`; название в интерфейсе может быть `FlashSprint`.

Либо импортировать существующую папку, в том числе найденную в окружении:

```sh
./tools/skills.py scan
./tools/skills.py import /absolute/path/to/my-skill
# При переименовании:
./tools/skills.py import /absolute/path/to/old-skill --name new-skill
./tools/skills.py check new-skill
./tools/skills.py install new-skill
```

Импорт копирует всю папку и сохраняет источник. При переименовании обновляет техническое
поле `name` и `$имя` в метаданных Codex. Заголовки и содержательные упоминания в тексте
нужно проверить отдельно. Существующий оригинал в каталоге импорт не перезаписывает.
Внутренние симлинки в скилле отклоняются: импортируйте самостоятельную переносимую папку.

После изменения **существующего** скилла копировать его заново не нужно. Для **нового**
скилла выполните `check` и `install`. Фонового наблюдателя и автоматического импорта нет.

## Команды

| Команда | Действие |
|---|---|
| `scan` | Инвентарь пользовательских каталогов трёх окружений, `.agents/skills` и репозитория; разные версии одного имени отмечены `diverged=True` |
| `status [имя…]` | Состояние каждой управляемой установки: linked / missing / conflict |
| `check [имя…]` | Проверка frontmatter, имени, структуры, переносимости и относительных Markdown-ссылок |
| `import <путь> [--name имя]` | Импорт целого скилла; без установки и изменения источника |
| `install [имя…] [--dry-run]` | Установка ссылок; повторный вызов не меняет исправные ссылки |
| `install [имя…] --replace` | Перенос конфликтующих установок в резервную копию, затем создание ссылок |
| `uninstall <имя…> [--dry-run]` | Удаление только ссылок на оригиналы этого репозитория; каталог и чужие установки сохраняются |

Конфликт без `--replace` останавливает **всю установку до изменений**. Резервные копии
лежат в `~/.local/state/personal-skills/backups/`; команда выводит точный путь. При
ошибке установки уже сделанные изменения откатываются. Удалённые из каталога скиллы
не очищаются автоматически: перед удалением оригинала выполните `uninstall`.

`scan` — инвентаризация, не автоматический импорт. Он не управляет встроенными
навыками и каталогами плагинов. Изменения сравниваются по SHA-256 содержимого всей
папки; одинаковые ссылки не считаются разными версиями. По одному хэшу нельзя
определить, какая из разных версий правильная.

Общие опции ставятся перед командой:

```sh
./tools/skills.py --json status
./tools/skills.py --repo /path/to/catalog --home /tmp/test-home install
```

Коды выхода: `0` — успешно, `1` — ошибка/отказ менять конфликт, `2` — обнаружены
missing/conflict/invalid или расхождения при инвентаризации. `install --dry-run`
с отсутствующими установками тоже возвращает `2`: это план, а не ошибка записи.
Операции записи сериализуются локальным lock-файлом репозитория.

## Проверки

```sh
uv run --with pyyaml python -m unittest discover -s tests -v
./tools/skills.py check
```

Тесты используют временные репозиторий и домашнюю папку. Они проверяют общие правки
через ссылки, повторную установку, конфликты, backup, откат ошибки, импорт,
переименование и безопасное удаление установок.

## FlashSprint

`skills/flash-sprint/` — спринт из обсуждения и диктовки: задачи, интерактивный HTML,
сохранённые статусы, Jira/PR, выполнение выбранного объёма и продолжение между чатами.
В Codex можно вызвать `$flash-sprint`; в остальных окружениях — попросить использовать
FlashSprint или выбрать навык доступным там способом.

## GitHub

Синхронизация пока только на одном компьютере. Инструмент не делает commit, push,
pull и не запускает фоновые задачи. История Git и публикация в GitHub — явные действия
владельца. После установки не перемещайте оригиналы в каталоги окружений: редактируйте
их в `skills/` или через установленные ссылки.
